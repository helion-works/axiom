# Changelog

All notable changes to Axiom (formerly AgentAV, before that MCPGuard) are recorded here. Versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

## [0.6.0] - 2026-11-26

- **Licence: Apache-2.0** (`LICENSE`, `NOTICE`).
- **Release preparation (Phase 5): four false-positive fixes, measured on a fresh held-out sample.** One shared definition of a non-production path (`smoke/`, `scripts/`, `bench/`, `demo/`, `.github/`, `*.smoke.*` added). `oauth_metachar` matches shell syntax only inside the quoted URL value, and its benchmark-specific path exception is removed. Secret-shaped literals that are vendor samples marked `EXAMPLE`, masked values, bare PEM headers, redaction arguments or CI secret fallbacks are no longer reported. A tool-name token alone (`spawn_`, `execute_`, …) is LOW for `shell_exec` unless the description or a command parameter confirms it, and a toxic combination is never more than one level above its weaker input. On a second 50-repository registry sample the rules had never seen (49 scanned): 1 CRITICAL (a false positive) and 20 HIGH (19 false positives). Details and the unfixed HIGH list: `LAUNCH_READINESS.md`.
- **Fixed:** a `package.json` or `pyproject.toml` containing non-ASCII text made the scan exit with `UnicodeDecodeError` on Windows.
- **Fixed: the built-in MCP CVE list is now real and version-aware** (`data/threat_intel.py`). It holds three published CVEs under their real identifiers and package names (CVE-2025-6514 `mcp-remote`, CVE-2025-49596 `@modelcontextprotocol/inspector`, CVE-2025-53109 `@modelcontextprotocol/server-filesystem`), each with the affected range and a link to its advisory. Before, two entries carried placeholder identifiers and package names that matched nothing, and any project depending on `mcp-remote` got two CRITICAL findings whatever its version, with a wrong fixed version (0.2.0; the fix is 0.1.16). Now a dependency is matched on its exact version: the lockfile's, or the manifest's when it is pinned exactly. An affected version is reported at the advisory's severity (one level lower for a transitive dependency), a patched version is not reported, and a range with no lockfile gets one INFO note. When OSV reports the same advisory it is counted once. The stored results in `proofs/` contain none of these findings, and the changed check adds none on the manifests and lockfiles of the 100 sampled registry repositories, the 7 reference servers and MCPSecBench at the measured commits, so the measured figures are unchanged.
- **Fixed: `axiom scan <package name>` raised `ImportError`** (since 0.5.0), so a scan by package name never ran. It now resolves the name through its registry and scans the source repository. `npm:` and `pypi:` prefixes and a version suffix (`pkg@1.2.3`, `pkg==1.2.3`) are accepted.
- **Fixed: the usage ping was never delivered.** `axiom check` started the request on a background thread and exited before it was made, while recording the attempt, so no ping left the machine. The command now waits for the request (3-second timeout) before it exits. A platform other than Windows, macOS or Linux is sent as `other`, not as the raw platform string.
- **Fixed:** the install id sent in a new installation's first usage ping was not saved, so its second ping used a different id.
- **Fixed:** text of any length where a version belongs in a manifest could end a scan with `ValueError`.
- **Documentation corrected:** OSV advisories are reported at MEDIUM (LOW when transitive), not at the advisory's own rating; a version range in a manifest is looked up in OSV at its lowest version even when a lockfile pins a later one; package targets are scanned from their source repository, not from the published archive. See Limitations in the README.
- **README and landing page:** the list of MCP incidents now describes each entry as what it was (published CVE, disclosed bug or research demonstration) and links to its source.
- **Removed settings that did nothing:** `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `REDIS_URL`, `NVD_API_KEY` and `LOG_FILE` were listed in `.env.example` and the README, but no code used them. Setting `SUPABASE_URL` did have one effect: the API stopped storing scans in SQLite and kept them in memory only. The API stores scans in SQLite; that is the only storage there is.
- **Fixed: the install hint for A2A signature checks named the wrong package.** The scanner's message and the README said `pip install axiom[a2a]`; `axiom` on PyPI is a different project. The extra is `axiom-scan[a2a]`.
- **Fixed: the CI package check failed on its own smoke scan.** The scan of the deliberately malicious fixture ends with exit code 2 by design; the check now expects that code. The example workflow no longer names a package that is not this one, and the workflow's documentation link points at the README.
- **Description:** Axiom is described as a security scanner for MCP servers and agent tooling, in the README, the package description, the command-line help and the SARIF tool name. The earlier tagline called it an antivirus; it scans and reports when run, and does not block, quarantine or remove anything. The README's Safety section now states that a live scan started with `--command` runs that command.
- **Disclaimer:** the README has a Disclaimer section and the landing page footer states that the software is provided as is, without warranty; both point to the licence.
- **`axiom owasp`:** the "Real Incidents" column of the Agentic Top 10 table is now "Published Example" and lists only the CVEs and research demonstrations that were checked against their source; rows with no checked example show a dash. The field in the coverage matrix is renamed from `real_incidents` to `published_examples`.
- **Proofs carry no local paths.** Every file under `proofs/` uses `<corpus>/…` in place of the absolute clone path.
- **TypeScript/JavaScript servers are parsed, not pattern-matched** (`app/analysis/ts_extractor.py`, tree-sitter). `server.tool()`, `registerTool()`, `registerResource()`, `registerPrompt()`, low-level `setRequestHandler(ListTools…/CallTool…)` handlers with per-`case` attribution, module-level `TOOLS` arrays, zod shapes (`.optional()`, `.default()`, `.describe()`), `jsonSchema2020(X.shape)`, JSON-schema literals, template/concatenated strings, `instructions` on `new McpServer(...)`, `handle.remove()/disable()/update()` and `removeTool()` are all read from the syntax tree. Every Phase 2 text rule now runs identically on Python and TS/JS. A TS port of the test bed's `evil_server.py` (`tests/fixtures/evil_server.ts`) scores the same 12/12 with the same finding ids and severities as the Python original. The regex extractor remains only as a fallback when the grammar wheels are missing.
- **The Agent Surface Map** (`app/analysis/surface_map.py`): a normalised, language-independent record of everything an agent is shown or could invoke — server name/instructions/transport/auth, each tool with its description, input schema, capability tags (`fs.read`, `fs.write`, `exec`, `net.egress`, `env`, `identity`, `install`), return-path literals and registration site, resources with content literals, prompts with message literals, and *mutations* (runtime `add_tool`/`remove_tool`, invocation counters, `listChanged`). Its **fingerprint** is sha256 over the canonical map (names + descriptions + schemas + instructions; whitespace-normalised). The Python and TS fixtures produce the same fingerprint. `axiom scan` results and JSON carry `surface_map` and `fingerprint`.
- New commands: `axiom surface <path>` prints the map; `axiom baseline <path>` stores it; `axiom drift <path>` diffs against the stored baseline (exit 2 on change); `axiom live … --source <dir|map.json|baseline>` compares the on-the-wire map with the source map and reports `surface_mismatch` findings (HIGH for a tool the source does not define or a changed description, MEDIUM for a changed schema or extra resource/prompt) — rug-pull detection without calling a tool.
- **Phase 4 validation (held-out).** The scanner was measured, frozen at commit `5f3d93b`, on corpora its rules had never seen: the seven official reference servers (`modelcontextprotocol/servers`), a 50-server sample of the official MCP Registry (25 most-starred of a random pool + 25 random, seed 20261104) and MCPSecBench (14 server-side cases). Before: every reference server rated *critical* (81 CRITICAL / 236 HIGH, all false positives), 36/50 registry servers rated critical, MCPSecBench 5/14. The fixes below were then made and everything re-measured. Numbers, dates and commits live in `docs/COVERAGE.md` (regenerated by `tools/coverage_ledger.py`); the write-ups are `FP_BASELINE.md` and `HELDOUT_RESULTS.md`; raw outputs are committed untouched under `proofs/`.
- **Severity policy** (`docs/SEVERITY.md`, `app/analysis/severity_policy.py`). Capability is not intent: a tool that reads files, runs a process or makes a request is an INFO/LOW note unless it combines with poisoning, injection, exfiltration, a secret or a rug-pull primitive on the same server. Transport findings depend on where the host is (loopback INFO, private range LOW, public HIGH). Whole-file code patterns (`realpath`, `symlink`, `..`, env reads, HTTP calls, `eval`) are capability notes. Toxic combinations need strict capabilities on both sides and blast radius never outranks its inputs. The risk level is set by the worst finding, so capability notes never add up to a "medium" server. Dependency advisories are matched to the **locked version** (package-lock.json, uv.lock, poetry.lock, Pipfile.lock), rated by the advisory, capped at HIGH, cached 24 h; `--no-deps` skips network lookups.
- **Two-tier text rules.** Hostile phrases keep their severity; imperative guidance the reference servers use in ordinary descriptions ("will succeed silently", "You should: 1.", "full scope") is steering language at MEDIUM. New `preference_override` (HIGH) for "use this tool rather than others" / "no matter how many arguments" / "replace the values with"; a leading `[important]` tag is an injection marker. `SYSTEM:` is case-sensitive.
- **New detectors** from the MCPSecBench misses: parameter→sink flows (`flow_<tool>_<param>_<kind>`: a caller parameter reaching `open()`, `subprocess`, `fetch()` unchecked; LOW after a validating call), self-rewritten descriptions (`rugpull_docstring_*`, the assigned text is scanned), function-local data on the return path, schema context parameters (`tools_list`, `conversation_history`, `system_prompt`…), documented-vs-schema mismatch, server-name squatting (in a source tree and across configured clients), shell metacharacters in OAuth metadata (CVE-2025-6514 pattern).
- **Replayable findings** (`rule_id`, `evidence`, `location`, `replay` on every finding; enforced by a unit test on static, live and config scans) and `axiom explain <id> [--from scan.json]`.
- **SARIF 2.1.0** (`--output sarif`, validated against the OASIS schema; one rule per Axiom rule with OWASP ASI/MCP mapping; GitHub Code Scanning upload documented) and **CycloneDX 1.5 AIBOM** (`--output aibom`: the server, every tool, resource and prompt as a component with capability tags and the Surface Map fingerprint; findings as vulnerabilities). `--fail-on <level>` on `scan` and `live`.
- **Provenance** (`app/analysis/provenance.py`): registry identity (`provenance_mismatch`), lookalike registry names from a different publisher (`registry_typosquat`), publishes under 7 days old (`provenance_fresh_publish`); cached 24 h. Scan JSON and the AIBOM carry the report.
- **Usage ping** (README, "Usage ping"): `axiom check` (and the no-argument run) sends anonymous counts at most once per 24 h; `axiom telemetry show|off|on|reset`; `AXIOM_TELEMETRY=0` / `DO_NOT_TRACK=1`.
- **Packaging and hygiene.** CI runs the suite on Linux/macOS/Windows × Python 3.10–3.12, the test-bed proofs and a clean-wheel smoke; nothing in CI publishes. `SECURITY.md` added; `LICENSE` is Apache-2.0. README rewritten around install, a real example, the coverage table, what is and is not detected, safety and limitations.
- **Renamed to Axiom.** The command is `axiom`, and it is the only command the package installs: the `agentav` and `mcpguard` command names used during development are not installed (`mcpguard` is another project's package name on PyPI). The PyPI distribution is `axiom-scan` (the name `axiom` is taken). Environment variables are `AXIOM_*`; `AGENTAV_*` and `MCPGUARD_*` still work as fallbacks. The data directory is `axiom`; an existing `agentav` or `mcpguard` directory is still used when the new one does not exist. The CLI module is `cli.axiom_cli` (`cli.mcpguard_cli` is a shim). The repository is `https://github.com/helion-works/axiom`. © 2026 Helion Works. Licensed under Apache-2.0.
- **Renamed to AgentAV** ("antivirus for AI agents"). The command was `agentav` during that stage of development. Environment variables are now `AGENTAV_*` (`AGENTAV_ALLOW_HOST_ACCESS`, `AGENTAV_DATA_DIR`, `AGENTAV_CI`); the old `MCPGUARD_*` names still work as fallbacks. The data directory is now `agentav`; an existing `mcpguard` directory is still used when the new one does not exist. The PyPI distribution is now `agentav`. The repository was renamed to `agentav`, the SARIF tool name and `/health` service name are `AgentAV`, and the temporary clone directory is `/tmp/agentav_scans`.
- Production guard: `POST /api/v1/scan/local`, `POST /api/v1/discover` and `/api/v1/scan/live/*` return 404 when `APP_ENV=production` unless `AGENTAV_ALLOW_HOST_ACCESS` is 1, true or yes. `GET /health` now includes `env` and `host_access`.

Phase 2 — detection gaps found by the in-house test bed (two deliberately vulnerable servers, 20 planted findings, two benign controls):

- **Fixed a false positive on benign tools.** The sleeper-pattern rule matched the bare word "count", so `word_count`, `count_rows` and `increment_counter` were reported as high-severity sleepers. A sleeper now needs a trigger condition ("after N calls", "on first use", "warm-up phase").
- **`agentav scan <path>` scans a local file or directory.** The same pipeline as a cloned repo runs in place; the engine never deletes a directory it did not create. Only the CLI resolves local paths; the REST API still accepts URLs and package names only.
- **AST-based extraction for Python servers** (`app/analysis/py_extractor.py`). Decorator arguments (`@mcp.tool(name=...)`, `description=`), any docstring style, FastMCP `@mcp.resource(...)` / `@mcp.prompt()`, `add_tool()` / `remove_tool()` registrations, parameter defaults and the strings a function returns are all visible now. The regex extractor remains the fallback for unparsable files and for JS/TS.
- **Live scans read what the server lists.** `initialize.instructions` is stored and scanned; resources are read (`resources/read`) and prompts fetched (`prompts/get`) with limits (25 each, 64 KB, text mime types, no `http(s)` URIs, no prompts with required arguments) and never `tools/call`. `--no-read` keeps the old list-only behaviour. New `LiveScanResult` fields: `server_instructions`, `resource_contents`, `prompt_messages`; JSON adds `resources_read` and `prompts_fetched`. `tools.listChanged=true` is reported LOW.
- **Per-tool capability findings.** `cap_<tool>_<capability>` names the tool that can execute shell commands, read or write files, dump the environment, or send data to a caller-chosen destination. New categories `shell_exec`, `file_read`, `file_write`, `env_dump`. Rules are strict: an ordinary filesystem server stays LOW. Toxic-combo and blast-radius findings are unchanged and now share one `classify_tool_capabilities()`.
- **New detectors and categories**: hard-coded egress URLs in tool bodies, descriptions, instructions, resources and prompts (`data_exfiltration`, small allowlist of well-known hosts); confusable tool names such as `fetch_urI` (`homoglyph`); invisible Unicode code points (`hidden_unicode`, CRITICAL); runtime `add_tool`/`remove_tool` and `listChanged` literals (`rug_pull_primitive`); injection markers in the strings a tool returns (`response_injection`); schema defaults that ask for `*`, `.all`, `offline_access` or a root path (`excessive_scope`); a tool that forwards a caller-supplied URL with a server-held credential (`confused_deputy`); descriptions that rewire other tools or servers (`tool_shadowing`). All are mapped to OWASP ASI and MCP Top 10 in `data/owasp_mcp_top10.json`.
- **Secret placeholder rule narrowed.** A value is a placeholder only when it is made of placeholder words (`your_api_key_here`), is a documented example (`AKIAIOSFODNN7EXAMPLE`), or is obvious filler. A real key that merely contains "test" or "example" is reported.
- **Remote transports rewritten (Phase 3, DVMCP).** `agentav live --url <endpoint>` speaks Streamable HTTP (POST to one endpoint, JSON or SSE replies, `Mcp-Session-Id`) and legacy HTTP+SSE (GET stream with `endpoint` event, POST to the announced URL, replies on the stream); the transport is auto-detected, `--transport` forces one, `--header`/`-H` adds request headers such as `Authorization`. The previous `MCPSSEClient`, which POSTed to `/message` and expected a JSON body, could not talk to any real server. `--sse` is kept as an alias. A session opened with no credential is reported HIGH (`live_<server>_no_auth`); `LiveScanResult.auth_provided` records it. REST `POST /api/v1/scan/live/sse` accepts both transports.
- **Rules learned from the 15 DVMCP challenges.** Credentials, tokens, flags and connection-string passwords inside served content (resources, prompts, instructions, tool return strings) are CRITICAL `credential_theft` (`*_secret_exposure`, values never reproduced); resources named internal/secret/admin/debug/token are `context_oversharing` (HIGH when the session was unauthenticated); parameters that pick another identity (`on_behalf_of`, `impersonate`, `as_user`…) are HIGH `identity_privilege`, parameters that carry an authorization decision (`approval_token`, `role`, `is_admin`…) MEDIUM; tools that install or load plugins/packages with `version="latest"` are `supply_chain`, as is served text that enables public-registry fallback; a tool whose body compares an invocation counter against a number is a `rug_pull_primitive`; near-duplicate tool names (`calculate_advanced` next to `calculate`, `get_user_roles` next to `get_user_role`) are `tool_shadowing`; injection markers inside module-level data the server stores and serves (preloaded documents, plugin registries) are `response_injection`.
- **Hygiene.** `live --output json` writes only the JSON document to stdout (multi-server mode emits one document: `{"schema_version": "0.5", "servers": [...]}`, which replaces the previous JSON array). `scan --output json` findings now include `file_path`, `line_number` and `recommendation`. stdout/stderr are reconfigured to UTF-8 at CLI entry so cp1252 consoles no longer crash. `pydantic` is pinned `>=2.9,<3` so AgentAV installs alongside `mcp>=2`. `local --path <file>` scans only that file unless `--include-defaults` is passed. Source files are read as UTF-8 regardless of locale.

## [0.5.0] - 2026-10-06

This release adds a second OWASP framework, three new commands and a handful of integration fixes. All new output fields are additive: existing CLI commands, REST endpoints and JSON fields behave as before.

### Added

- **OWASP MCP Top 10 mapping.** Every finding now carries both `owasp_asi` (OWASP Agentic AI Top 10) and `owasp_mcp` (OWASP MCP Top 10, v0.1 beta) where a mapping applies. The MCP mapping lives in `data/owasp_mcp_top10.json`, so IDs, titles and coverage levels can be updated without code changes. New detectors cover hard-coded secrets (MCP01), unpinned install sources (MCP04), exec/shell sinks inside tool handlers (MCP05), servers bound to all interfaces (MCP07), missing tool-call logging (MCP08, low confidence) and tools or resources that expose bulk data (MCP10).
- `mcpguard owasp --framework asi|mcp|all` shows either coverage matrix or both. The default (`asi`) prints the same table as before. Every `partial` and `gap` item comes with a one-line reason.
- Scan results include an `owasp_mcp_coverage` block next to `owasp_coverage`.
- JSON output carries `schema_version: "0.5"`.
- **`mcpguard discover`**: shadow MCP discovery. It lists every MCP server configured in local MCP clients (Claude Desktop, Claude Code, Cursor, Windsurf, VS Code, Cline, Zed, Gemini CLI, Continue and project-level files). It records each server's transport, install source, version pin and env var *names*, never their values, and redacts anything that looks like a credential. With `--allowlist`, each server is classified `approved`, `unapproved` or `unknown-version`, and every unapproved server raises one HIGH finding mapped to ASI04 / MCP09. Optional `--scan` and `--processes` modes are included. REST: `POST /api/v1/discover`.
- **`mcpguard a2a`**: static scanning of A2A agent cards, pinned to A2A specification 1.0.0. It checks transport, schema validity, missing or weak authentication, card signatures (JWS), interface and provider host mismatches, poisoned skill text, dangerous skills reachable without auth, extended-card exposure, and legacy protocol versions. Scanning is passive: it reads the card, at most one JWKS document and at most one extended-card GET. REST: `POST /api/v1/a2a`, which has mandatory SSRF protection.
- **`mcpguard threatmodel`**: deterministic threat model generation from a scan, a discovery run, A2A cards, or any combination of them. It builds a system model with components, data flows, trust boundaries, assets and explicit assumptions, then evaluates the rule catalogue in `data/threat_catalogue.json`. Each threat is tagged with STRIDE, CSA MAESTRO layer, OWASP ASI and OWASP MCP, and scored as likelihood x impact. The command writes a Markdown report (with a Mermaid data-flow diagram) or JSON. With `--ai`, it can add clearly separated AI suggestions without changing any deterministic score. REST: `POST /api/v1/threatmodel`, `GET /api/v1/threatmodel/{id}` and `GET /api/v1/threatmodel/{id}/report.md`.
- New optional extra `mcpguard[a2a]` (PyJWT with crypto, jsonschema), used for agent card signature verification and full JSON-schema validation. Without it, `a2a` still runs: it falls back to a structural schema check and reports signatures as unverified. The `all` extra now includes these packages too.
- New `ANTHROPIC_MODEL` setting (see `.env.example`). It selects the Claude model for every AI feature and defaults to the model used before, so behaviour is unchanged.
- File format reference for the allowlist and the threat rule catalogue in `docs/FILE-FORMATS.md`.

### Changed

- Version is 0.5.0 in package metadata, the FastAPI app, `/health`, the CLI `version` command and the GitHub Action's SARIF output.
- `mcpguard scan --output json` now also includes `schema_version`, the full `server_profile` (tools, resources, prompts and env var names), and each finding's `id` and `description`. All of these are additive. This lets the file be passed straight to `mcpguard threatmodel --from-scan`.
- The AI model id is no longer hard-coded in `app/analysis/ai_analysis.py` and `app/analysis/threat_model/ai_enrich.py`. Both now read `ANTHROPIC_MODEL`.
- README: added an MCP Top 10 coverage table and updated the ASI07 row now that A2A agent card scanning exists. Live A2A message inspection is still listed as a gap.

### Fixed

- `POST /api/v1/scan` used to return `owasp_coverage: null`. It now fills in both `owasp_coverage` and `owasp_mcp_coverage`.
- The CLI failed to import because `typing.List` was used without being imported. Found and fixed during Phase 1.
- `threatmodel --from-scan scan.json` built a model with no tools when `scan.json` came from `mcpguard scan --output json`, because that output did not include `server_profile`. It does now. Finding ids are included as well, so evidence links and the remote-server authentication check work from CLI output.
- `mcpguard scan --output json > scan.json` used to write invalid JSON, because the progress spinner and the scan-history note were printed to stdout along with the document. In JSON mode they now go to stderr.
- Findings from `discover --scan` (local config checks and static package scans) were not stamped with OWASP references. They now carry both `owasp_asi` and `owasp_mcp`.
- README linked to an `OWASP-COVERAGE.md` file that did not exist. The link now points to `mcpguard owasp --framework all` and the coverage tables in the README.
